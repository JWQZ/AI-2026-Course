# 人工智能原理与应用（2026）课程大作业提交说明

## 提交前必看：你怎么能直接 commit 到我的 master 分支啊

你怎么直接往本仓库的 `master` 分支提交了？！GitHub 作业提交要走 Pull Request 流程啊！

先把本仓库 fork 到自己的账号，再从课程指定的基础分支创建一个和组号一致的分支，比如 `group-01`。然后把作业放进所选任务对应的目录，例如第 1 组做 Agent，就提交到 `Agent/group-01/`。别放错题目，也别把几个组的作业混在一起。

提交前检查一下：代码和 `README.md` 都在，运行方法写清楚，结果展示能打开。确认没问题后，把分支推送到自己的 fork，再向本仓库的 `master` 分支发起 Pull Request。PR 标题写清题目和组号，描述里说明项目内容、如何运行、结果在哪里。

助教如果在 PR 里提出修改意见，就在原分支继续修改，让更新自动进入同一个 PR。不要另开重复 PR，也不要直接推本仓库的 `master` 分支，更不要 force push。文件夹放错、说明不清或结果打不开，都会被退回修改。按流程提交，节约双方时间，谢谢合作！

## 题目目录

| 题目 | 提交路径 |
| --- | --- |
| 大模型后训练 | `PostTraining/group-XX/` |

`XX` 为课程统一分配的两位组号，且全班唯一。每组仅由组长或指定代表提交，并只修改本组目录。

## 📌 提交规范

1. **分组目录**：在所选任务对应的目录下新建本组文件夹，命名为 `group-XX/`，例如 `Agent/group-01/`。
2. **文件结构**：组目录中应包含项目代码文件夹和 `README.md`。README 简要介绍项目，说明环境与使用方法，并展示运行结果。
3. **分支命名**：每次提交使用一个与组号一致的分支，例如 `group-01`。分支名和组目录中的组号必须一致。
4. **忽略文件**：不要提交缓存、临时文件、编译产物、虚拟环境、大型数据集或模型权重。项目专属忽略规则请放在组目录内的 `.gitignore` 中；不要为单组作业修改仓库根目录的公共 `.gitignore`。

## 📌 提交流程

1. 将本仓库 Fork 到自己的 GitHub 账号。
2. 在个人 fork 中，从课程指定的基础分支创建 `group-XX` 分支，例如 `group-01`。
3. 在对应任务目录下创建 `group-XX/`，并放入本组作业文件。
4. 提交更改并推送到自己的 fork。
5. 向本仓库的 `master` 分支发起 Pull Request。标题注明题目和组号，描述项目内容、运行方法和结果位置。
6. 根据助教在 PR 中的意见，在原分支继续修改；审核通过后等待合并到 `master`。

## 📌 注意事项

- 请勿直接向本仓库的 `master` 分支提交。
- 每组由组长或指定代表负责提交。
- 请保持目录和文件命名清晰、完整；提交前确认说明和结果文件可正常查看。
